# VPS Stack (single host, Docker Compose)

A compact business stack for **one public VPS**: company web site, mail,
file sharing with in-browser office editing, a password vault, uptime
monitoring and container management. Caddy sits in front of every web service
and obtains Let's Encrypt certificates automatically.

Unlike the parent [`small-scale/`](../) stack (on-premise, Samba AD + Authentik,
Cloudflare Tunnel), this variant has no central directory: each service keeps
its own user accounts. Use it when a single rented server must host everything
and inbound ports 80/443 and the mail ports are reachable.

| Service | Subdomain | Container | Purpose |
| --- | --- | --- | --- |
| Caddy | — | `caddy` | Reverse proxy, automatic HTTPS, HTTP/3 |
| WordPress + MariaDB | `DOMAIN`, `www.DOMAIN` | `website`, `website-db` | Company web site |
| Poste.io | `mail.DOMAIN` | `mailserver` | SMTP/IMAP, webmail (Roundcube), Rspamd, ClamAV |
| Nextcloud + PostgreSQL + Redis | `cloud.DOMAIN` | `nextcloud`, `nextcloud-cron`, `nextcloud-db`, `nextcloud-redis` | Files, calendar, contacts, tasks |
| ONLYOFFICE Docs | `office.DOMAIN` | `onlyoffice` | Word/Excel/PowerPoint editing inside Nextcloud |
| Vaultwarden | `pass.DOMAIN` | `vaultwarden` | Bitwarden-compatible password vault |
| Uptime Kuma | `status.DOMAIN` | `uptime-kuma` | Service and host monitoring |
| Portainer CE | `portainer.DOMAIN` | `portainer` | Container management UI |
| Cockpit (host, optional) | `https://VPS_IP:9090` | — (apt package) | Host administration and file manager |

Files in this directory:

- `docker-compose.yml`: all services, pinned image tags, segmented networks
  (`edge` for proxied services, internal-only `nextcloud_backend` and
  `website_backend` for the databases)
- `Caddyfile`: one site block per subdomain
- `.env.example`: template for the git-ignored `.env`

## Sizing

Plan for **at least 8 GB RAM** and 4 vCPU. ONLYOFFICE (~2 GB), ClamAV
(~1.2 GB) and Nextcloud are the largest consumers. On a 4 GB host set
`DISABLE_CLAMAV: "TRUE"` for `mailserver` in `docker-compose.yml`.

## 1. DNS

Create these records at your DNS provider (replace `VPS_IP`):

| Type | Name | Value |
| --- | --- | --- |
| A | `@`, `www`, `mail`, `cloud`, `office`, `pass`, `status`, `portainer` | `VPS_IP` |
| MX | `@` | `mail.DOMAIN` (priority 10) |
| TXT | `@` | `v=spf1 mx -all` |
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:postmaster@DOMAIN` |
| TXT | DKIM selector (step 4) | value generated by Poste.io |

Ask the VPS provider to set the **reverse DNS (PTR)** of `VPS_IP` to
`mail.DOMAIN`, and confirm outbound port 25 is not blocked. Without both,
other mail servers will reject or junk your mail.

## 2. Host preparation and start

```bash
sudo hostnamectl set-hostname mail.DOMAIN

# Optional: Cockpit host panel with the 45Drives Navigator file manager
sudo apt update && sudo apt install -y cockpit cockpit-sosreport
curl -sSL https://repo.45drives.com/setup | sudo bash   # review the script first
sudo apt install -y cockpit-navigator
sudo systemctl enable --now cockpit.socket

# Deploy (Docker Engine with the Compose plugin must be installed)
sudo mkdir -p /opt/sovereign-vps && cd /opt/sovereign-vps
# copy small-scale/vps/{docker-compose.yml,Caddyfile,.env.example} here
sudo cp .env.example .env && sudo chmod 600 .env && sudo nano .env
sudo docker compose up -d
sudo docker compose ps
```

Caddy requests certificates as soon as DNS resolves to the VPS; check
progress with `sudo docker compose logs -f caddy`.

All state lives under `/opt/sovereign-vps/data/` (bind mounts). Back up that
directory together with `.env` and the `Caddyfile`; stop the stack or dump the
databases first for a consistent copy:

```bash
sudo docker compose exec nextcloud-db pg_dump -U "$NC_DB_USER" "$NC_DB_NAME" > nextcloud.sql
sudo docker compose exec website-db sh -c 'mariadb-dump -uroot -p"$MARIADB_ROOT_PASSWORD" --all-databases' > website.sql
```

## 3. First logins (do these immediately)

| Service | URL | First step |
| --- | --- | --- |
| Portainer | `https://portainer.DOMAIN` | Create the admin user within 5 minutes; otherwise the setup locks (`sudo docker restart portainer` resets the timer) |
| Poste.io | `https://mail.DOMAIN/admin` | Create the admin mailbox (`postmaster@DOMAIN`) |
| Nextcloud | `https://cloud.DOMAIN` | Log in with `NC_ADMIN_USER` / `NC_ADMIN_PASSWORD` |
| Vaultwarden | `https://pass.DOMAIN` | Create accounts, then set `VW_SIGNUPS_ALLOWED=false` and `docker compose up -d vaultwarden`; admin panel at `/admin` |
| Uptime Kuma | `https://status.DOMAIN` | Create the admin user, add monitors for each subdomain |
| WordPress | `https://DOMAIN` | Run the installer |
| Cockpit | `https://VPS_IP:9090` | Log in with a sudo-capable host user |

## 4. Mail: DKIM and TLS

1. In Poste.io admin open **Virtual domains → DOMAIN → DKIM key → Generate new key**
   and publish the shown TXT record at your DNS provider.
2. **TLS for SMTP/IMAP:** Caddy terminates TLS only for the web UI. In
   **System settings → TLS certificate** enable Let's Encrypt for `mail.DOMAIN`.
   The HTTP-01 challenge reaches Poste.io through Caddy (Let's Encrypt follows
   Caddy's HTTP→HTTPS redirect), so no extra port is needed.
3. Verify with an external checker (e.g. mail-tester.com): SPF, DKIM, DMARC and
   PTR should all pass.

## 5. Nextcloud ↔ ONLYOFFICE

1. In Nextcloud open **Apps → Office & text**, install **ONLYOFFICE**.
2. **Administration settings → ONLYOFFICE**:
   - Docs address: `https://office.DOMAIN`
   - Secret key: the `ONLYOFFICE_JWT_SECRET` value from `.env`
3. Save; documents now open and co-edit in the browser.

CalDAV/CardDAV discovery (`/.well-known/caldav`, `/.well-known/carddav`) is
handled in the `Caddyfile`; Caddy has no request-body limit, so the 10 GB PHP
upload limit is the effective cap.

## 6. Firewall

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443          # tcp + udp (HTTP/3)
sudo ufw allow 25,465,587,993,4190/tcp
sudo ufw allow from ADMIN_IP to any port 9090 proto tcp   # Cockpit, admin IP only
sudo ufw enable
```

**Docker bypasses UFW for published ports.** UFW rules do not restrict ports
that `docker-compose.yml` maps; that is why the compose file publishes only the
ports listed above and no admin ports (the Portainer, Uptime Kuma and
Vaultwarden UIs are reachable only through Caddy). To restrict a published port,
use the `DOCKER-USER` iptables chain or remove the mapping.

## Hardening notes

- Portainer mounts the Docker socket, which is root-equivalent on the host
  even read-only. Consider stopping it when not in use
  (`docker compose stop portainer`) or restricting `portainer.DOMAIN` to an
  admin IP in the `Caddyfile` (`@admin remote_ip ADMIN_IP`).
- Store `VW_ADMIN_TOKEN` as an Argon2 hash (see `.env.example`).
- Keep `chmod 600 .env`; it holds every database and admin password.
- Upgrade Nextcloud one major version at a time; bump the tag in both
  `nextcloud` and `nextcloud-cron`.

## Migrating from Nginx Proxy Manager

An earlier draft of this stack used Nginx Proxy Manager. Caddy replaces it and
needs no admin UI or port 81: the `Caddyfile` is the whole proxy configuration.
To switch an existing deployment, run `docker compose down` with the old file,
replace the files, add `ACME_EMAIL` to `.env`, and start again. All other data
paths under `data/` are unchanged; `data/npm/` can be deleted afterwards.
Uptime Kuma 1.x data is migrated to 2.x on first start (one-way, back up
`data/uptime-kuma/` first).
